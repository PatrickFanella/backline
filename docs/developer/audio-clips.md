# Approved audio clips and soundboards

Managers explicitly enable `clipsEnabled` in audio settings before approving uploads. Approval can be prepared with audio playback disabled. The managed dashboard accepts a title, source or creator, license or permission record, original/licensed provenance choice, reviewed confirmation and the WAV file. Approval attribution records the manager's Discord ID. These are manager declarations, not automated verification of licensing.

Uploads accept a deliberately narrow subset of [RIFF/WAVE](https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff-): canonical uncompressed 16-bit PCM with a sixteen-byte format chunk followed directly by sample data, mono or stereo, 44.1 or 48 kHz, 0.05–15 seconds, at most three MiB. Header sizes, encoding, sample rate, byte rate, frame alignment and actual sample duration must agree. Extra chunks and other media formats are rejected. Playback uses approved stored bytes through FFmpeg's pipe-only input; the feature does not fetch media URLs.

Each server stores at most one hundred clips and fifty MiB of binary data. Upload transactions share the server lock and use a content hash to deduplicate bytes. Metadata endpoints return no binary data. `/clip search` finds approved clips by title; `/clip play` uses the existing DAVE voice runtime, current membership and voice permissions. The requester or a current DJ can interrupt playback with `/audio stop` or `/audio skip`. The runtime rechecks approval and clip settings during playback. Removing a clip withdraws approval and deletes its bytes, including when playback is disabled.

Managers save at most twenty named soundboards, each containing one to twenty distinct clips from the same server. `/clip boards` lists them. `/clip queue-board` atomically appends the board under current DJ authority, with both queues and clips enabled, then a DJ explicitly starts it. A withdrawn or expired clip makes a board unavailable until it is edited. Completed clips advance through the queue while preserving its original voice channel and overall duration limit; an actor moving elsewhere cannot move subsequent playback automatically.

Unused clip bytes expire ninety days after creation or the latest approved playback request. Cleanup deletes at most one hundred per maintenance pass. Saved boards and playlists remain within their explicit count limits until a manager deletes them; stale references cannot play a withdrawn source. Ordinary clip completion records a stopped playback, while decode/voice failure records failure and retains an interrupted queue entry for explicit recovery. The additive migration creates two tables without altering previous histories.

Local verification applies all twenty-six migrations to a fresh PostgreSQL database with eighty-four domain tables and removes it afterward. Thirty-one economy, entertainment, queue and clip checks cover concurrent claims/reservations, retained interruption, server isolation, quota races, fifty-MiB limits, atomic boards, stale approval, disabled withdrawal and expiry. WAV unit checks reject malformed headers, sizes, frames and duration. HTTP checks cover raw upload, authorization denial before storage, metadata scoping and oversized bodies. Dashboard checks cover searching, explicit approval, board saving and withdrawal. A generated original tone decoded to the expected 48-kHz stereo PCM byte count. These checks do not qualify actual Discord listening, simultaneous servers, reconnect, authenticated owner browser use, hosted CI, deployment, application restart or rollback. The private pilot remains on its previously pinned revision.
