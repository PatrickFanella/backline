# Audio queues and playlists

The audio module remains disabled by default, and `queuesEnabled` requires an explicit manager choice. Existing `/radio` playback uses published SomaFM sources and the DAVE-capable voice runtime. `/audio enqueue` adds a one-to-thirty-minute station segment; a current DJ explicitly starts the queue with `/audio start`. Members have ten pending entries each and each server has fifty. Playlists have at most fifty entries, and each server has twenty saved playlists.

`/audio` exposes queue inspection, pause, resume, volume, skip, stop, clear, shuffle, loop, save, load, list and delete. Starting, saving/loading, shuffle, loop and clear require current DJ permission. Pausing, resuming and changing volume require the requester or a DJ in the current channel. Volume cannot exceed the server limit. The requester or DJ skips immediately; other current human listeners each have one vote, with half of current listeners required. Departed votes are removed before counting. Loading a playlist uses the current actor and voice channel rather than inheriting its creator's authority.

Pending entries and saved playlists are server-scoped database records. A transaction and server advisory lock reserve one queue claim at a time. Stale completion cannot consume another claim's entry. Completed entries are removed or rotated for looping; failed playback and interruptions preserve the pending entry. Runtime maintenance renews a two-minute claim lease. Expired claims become interrupted, and an explicit DJ start is required. Settings loss, permission loss, empty-channel timeout and source/voice failure stop playback. The configured duration limit applies to an entire queue run, including looping; the next run requires an explicit start.

The additive migration creates two tables and preserves existing voice history. Six fresh PostgreSQL checks qualify claim concurrency, stale completion, lease recovery, retained interruption, loop rotation, capacities, malformed sources, playlist isolation, current DJ authority and disabled settings. Unit checks cover distinct current skip votes, current-channel controls, volume caps and revoked/banned actors. Existing source, command/module and dashboard settings checks remain relevant. These checks do not establish simultaneous real Discord playback in two servers, actual reconnect behavior, owner browser configuration, hosted CI or deployment. The private pilot remains unchanged.
