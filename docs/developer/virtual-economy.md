# Fictional server economy

The opt-in `economy` module adds `/economy join|leave|balance|history|inventory|shop|daily|coin|buy|adjust`. Every command replies privately. Points have no cash value; this module has no payment, withdrawal or real-money exchange path. Games and the shop require separate manager configuration and default to disabled. Members must explicitly join each server economy before earning, playing or buying.

The default currency name is Credits and daily reward is one hundred, configurable from one to one thousand. Daily claims use UTC calendar dates. A balance must remain between zero and one million. A coin game chooses heads/tails with cryptographic randomness and accepts a zero-to-one-hundred-point fictional bet. Matching the member's choice adds the bet; otherwise it subtracts it. Both possible outcomes must fit the balance limits before playing. The outcome persists once per interaction, with a ten-second member cooldown. New balance actions are limited to ten per minute per actor; receipt replay and participation withdrawal remain available at the limit.

The shop contains eight original fictional objects described by repository-authored text, without imported artwork. Fixed prices are visible in `/economy shop`; members buy one to ten objects at a time and retain at most ninety-nine of each type. Purchases commit the balance, inventory and ledger entry together. The server transaction lock serializes rewards, games, purchases, manager adjustments and configuration changes. Concurrent or restarted handling of the same interaction returns the persisted receipt. Different requests cannot double-claim today's reward or spend the same points twice.

Manager adjustments require fresh Manage Server permission, current target membership and an opted-in target. The ledger records the configuring actor, affected member, signed change, resulting balance and reason. The dashboard exposes the latest one hundred entries through current managed-server authorization. Member commands expose only the caller's balance, inventory and latest ten entries. Bot accounts and application-banned accounts cannot participate; banned members can still withdraw participation while installed and present.

Leaving preserves balances, inventory and the last daily claim. It cannot reset reward eligibility. Participation changes keep a monotonic interaction ID, rejecting older changes after a newer join/leave. They do not consume balance-ledger capacity, so withdrawal still works when the ledger is full or the module is disabled. No game notifications or unsolicited direct messages are sent. A user can stop participation with `/economy leave`.

Limits are one thousand retained accounts and one hundred thousand balance receipts per server. Receipts expire after ninety days in bounded batches. Balances, inventories, participation and reward history fields persist; account deletion and personal-data requests remain separate controls. Only Discord interaction IDs no older than five minutes are accepted, preventing replay after receipt retention. Schema migration is additive and new modules are disabled by default. Rolling the application back does not remove economy records.

## Qualification

Ten PostgreSQL checks passed on a fresh disposable database with twenty-three migrations and seventy-eight domain tables. They cover opt-in, daily deduplication, purchase races/receipt replay, guild isolation, coin persistence/cooldown, withdrawal while disabled, rejoin eligibility, manager attribution/revocation, bounds, stale changes, receipt expiry, full ledger withdrawal and action limits. Two dashboard checks cover explicit configuration without enabling the module and unavailable ledger reads. Both app builds passed. Hosted CI, current owner browser behavior, real Discord commands and restart/rollback remain live qualification gates; the private pilot has not enabled this module.
