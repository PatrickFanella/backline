# Provider notifications

The opt-in `integrations` module adds `/feed add|list|remove`. Managers add a source in its destination text or announcement channel: a lowercase Twitch login, a YouTube `UC…` channel ID, or a public HTTPS RSS/Atom URL. The dashboard shows source, baseline, outage/backoff and delivery states. Configuration requires current Manage Server and channel access; delivery rechecks the configuring manager and bot permissions.

Twitch uses a server-side app token from `TWITCH_CLIENT_ID` and `TWITCH_CLIENT_SECRET`, validates it when obtained and hourly, and reads streams from the fixed Helix endpoint. The stream ID is the notification identity. Credentials and tokens never enter source configuration or receipts. See [Twitch client credentials](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/#client-credentials-grant-flow) and [Get Streams](https://dev.twitch.tv/docs/api/reference/#get-streams).

YouTube needs operator `YOUTUBE_API_KEY`. It reads the channel’s uploads playlist and its latest fifty items; video ID identifies the event. This adapter covers public uploads, without promising live-stream start notifications. See [YouTube playlist items](https://developers.google.com/youtube/v3/docs/playlistItems/list).

RSS/Atom uses pinned public DNS addresses for each HTTPS request. Any private/mapped/reserved result is rejected. Redirects, user/password URLs and nonstandard ports are unsupported. DNS has a five-second deadline; a request has a ten-second deadline and a 512 KB response limit. XML declarations of entities/DOCTYPE and nesting above thirty-two elements are rejected. Up to one hundred entries are parsed; valid entries need a HTTPS link, stable ID/link and publication/update date. Feed HTML is stripped from titles. Parser and address dependencies are pinned to `fast-xml-parser` 5.11.2 and `ipaddr.js` 2.5.0; [parser upstream](https://github.com/NaturalIntelligence/fast-xml-parser) documents its API.

The first successful poll records a baseline without sending history. Subsequent items need a publication instant after that baseline and within the preceding day. External identities are hashed and unique within each feed. Reservations and jobs share the server transaction lock. Reconnecting retains identities and baseline; it can notify a new item from the last day, without replaying older history. Future-dated entries wait for a later poll. Twitch polls no faster than two minutes, YouTube/RSS fifteen minutes; failures back off from two minutes to six hours. Poll windows are claimed atomically and batches rotate, with polling separate from Discord job delivery.

Limits are twenty retained feeds and five thousand receipts per server, plus the shared one-thousand active job limit. Removing a feed disables it and cancels pending events under the server lock. Re-adding a disabled source can change its destination. Notification mentions are suppressed. Confirmed sends persist a message ID for readback; uncertain sends are held for investigation without replay. Terminal/baseline receipts expire after ninety days; held/leased receipts remain bounded investigation records. No automatic deletion of a feed or its baseline occurs.

## Qualification

Seven PostgreSQL checks pass on a fresh disposable database with nineteen migrations and seventy-one domain tables. They cover baseline suppression, concurrent/restarted reservation, concurrent delivery and receipt readback, lost-send holds, removal, outage backoff, current authority and server isolation. Nine adapter/transport checks cover RSS/Atom identities, XML limits, private/mapped address rejection, pinned connection DNS, redirects, YouTube uploads and redacted failures. Two dashboard checks distinguish baselines from uncertain sends and failed reads. Both app builds and changed-file lint pass.

These fixtures prove local behavior. Each provider still needs a natural new event delivered to the authorized pilot destination, as well as hosted CI. The private configuration has Twitch credentials but no YouTube API key at this qualification point. RSS needs an owner-selected feed. Read-only Twitch requests succeeded for both `subcult` and `patrick__eff`; both returned zero live items. This confirms credentials/API access and does not prove notification delivery.
