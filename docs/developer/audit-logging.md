# Server audit logging

The `audit-log` module sends selected member joins/departures, message edits/deletions, member role changes, role creation/deletion and delivered moderation cases to a server log channel. Configure the channel, event selection, retention days and message-content choice on the server setup page. `/settings` preserves existing configuration when toggling a module.

Set `BOT_MEMBER_INTENTS=true` and `BOT_MESSAGE_INTENTS=true` in the operator environment, enable the corresponding privileged member intent in Discord's developer portal and restart the bot before enabling this module. `BOT_MESSAGE_CONTENT_INTENT=true` and the portal's Message Content intent are additionally required to capture message text. Existing `BOT_ACTIVITY_INTENTS=true` also supplies these intents. Missing required intents keep the module inactive. Metadata remains available without message text; a cache-missing deletion records `cached=false` and unavailable content.

Content retention starts disabled. Turning it off scrubs `content`, `before` and `after` from existing local records and from outgoing queued events. Reducing retention clamps existing records to the shorter expiry. Records expire after 1–90 days; the running bot deletes expired rows at least once a minute. A stopped bot cannot run cleanup, but history reads and deliveries exclude expired records. Messages already sent to Discord remain subject to that channel's Discord retention and deletion controls.

Event capture persists a server/event key before enqueuing notification. The worker recovers interrupted capture-to-queue handoffs. Duplicate deletion and join events reuse one record. Member role updates and uncached departures use a unique capture key because Discord does not supply a durable event ID for those events; reconnect replay deduplication for those event classes is not established. Every destination is fetched through the event's guild, so a channel from another server cannot receive it. All mentions are disabled.

Delivery records the returned Discord message ID. A reservation prevents a second sender from replaying a notification; transport uncertainty remains held for investigation. Disabling the module cancels queued sends. The audit history API is `GET /guilds/:guildId/modules/audit-log/history`, protected by current server management authorization and limited to 100 unexpired records.

Validation: five real PostgreSQL tests cover event deduplication, destination scoping, content scrubbing, uncertainty and handoff/expiry recovery. On October 4, 2026, server `947948179897327686` received a real Gateway message-delete event in a disposable private channel. The worker delivered its audit notification, recorded message ID `1556404087522598913`, and a Discord fetch confirmed that message existed. The record retained no content. The module was disabled, the fixture channel removed and the test bot stopped. Member/role event delivery, human dashboard OAuth and sustained pilot observation remain separate gates.
