# Member suggestions

The opt-in `suggestions` module has a manager-selected server text channel. Configure its channel ID in Server setup, then enable the module. Members submit `/suggest create idea`. Backline publishes a message with Support and Oppose buttons. Each member has one vote per suggestion and may change it while the idea is open. Use `/suggest view id` for current totals, delivery state and the staff decision; the original channel message directs readers to that view.

Managers use `/suggest review id decision reason` to accept or decline an idea. The stored decision includes the reviewer and reason, and closes voting. Server membership, channel visibility and application-account status are rechecked for submissions, votes and reads. Review requires current Manage Server permission. The bot requires View Channel, Send Messages and Read Message History at publication and readback. Changing the destination prevents publication of pending ideas queued for the previous channel.

Submissions are limited to ten per member per day and one thousand retained ideas per server. Each idea accepts at most ten thousand distinct voters. A suggestion and its delivery job are reserved atomically under the server lock. Competing execution uses the persisted receipt. An uncertain publish remains held without automatic replay. Completed records, votes and job attempts expire together after thirty days; leased or held jobs preserve their investigation records within the server cap. Notification mentions are disabled.

PostgreSQL checks cover duplicate reservation, real worker publication, changeable votes, server isolation, current staff authority, closed voting, uncertain sends and content/receipt retention. Component checks cover saving without enabling and rejected saves. Natural Discord submission, button voting and staff review remain qualification gates. This is another E05 implementation slice; it does not complete the remaining utilities or public release.
