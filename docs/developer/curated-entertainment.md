# Original entertainment and collections

Entertainment is a disabled-by-default server module. `/fun joke`, `/fun eightball` and `/fun dice` return private entertainment replies. Managers review and explicitly approve each original layout before `/fun meme` accepts it. The dashboard offers sample previews and retained trade history. Saving approvals preserves the module's enabled state.

Three templates use original Backline text and geometric layouts; their source and repository license are exposed in the catalog. No imported illustrations or character art are included. Rendering uses pinned Sharp 0.35.5, fixed 512px SVG geometry and escaped captions of at most sixty characters. Four simultaneous renders, two native worker threads, a five-second processing timeout and a one-megabyte output limit bound each process. Caption text and rendered images are not stored. The container supplies DejaVu fonts separately through `font-dejavu`; see [DejaVu licensing](https://dejavu-fonts.github.io/License.html) and [Sharp installation requirements](https://sharp.pixelplumbing.com/install/).

Collection claims and trades require enabled entertainment and economy, an explicit manager collection setting, and individual economy participation. `/fun collect` grants one of the eight fictional catalog objects per UTC day. Leaving and rejoining preserves the claim date. Each member can hold ninety-nine of each object, including inventory reserved for trades.

`/trade offer` reserves one to ten objects for a named participating buyer for fifteen minutes. The price is a total fictional points amount, including zero for gifts. Only the named buyer accepts. Acceptance exchanges balances and objects in one transaction and records both ledger entries. The seller cancels or the buyer declines; opting out cancels pending offers involving that member. Cancellation and expiry return reserved objects even when the modules have since been disabled. No game or trade notifications are sent.

Fresh membership and current module settings are checked before new actions. Per-server advisory locks serialize claims, purchases, reservations and acceptance. Replayed interaction IDs return the persisted result without rerolling or spending twice; IDs outside the bounded Discord interaction timestamp window are rejected. A server retains at most ten thousand game receipts and one thousand trade records. Members can make five new entertainment requests per minute, fifty trade offers per rolling day, and have five pending incoming and five outgoing offers. Game receipts expire after seven days; completed trade records after thirty days. Pending reservations are returned before their records become eligible for deletion.

Local qualification uses an isolated PostgreSQL database with all twenty-four migrations and eighty domain tables; it is dropped afterward. Eighteen economy/entertainment database checks cover concurrent claims, purchases and acceptance, insufficient funds, reserved capacity, server isolation, disabled-module withdrawal and expiry. Native renderer checks and dashboard component checks cover PNG output, explicit approval saving and blob URL cleanup. These checks do not establish live Discord behavior, an authenticated owner dashboard flow, hosted CI, restart qualification or deployment. The private pilot remains on its previously pinned revision.
